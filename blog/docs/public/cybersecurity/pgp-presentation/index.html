What is PGP?

Public key

  • Share it with anyone
  • Locks messages for you and checks your signature

Private key

  • Never leaves your device
  • Unlocks your messages and signs what you send
Encrypt: lock with the receiver’s public key
Sign: seal with your private key
1991 PGP by Phil Zimmermann
1998 OpenPGP open standard
2024 RFC 9580 (used today)

How CipherChat uses PGP

Create account

Password to sign in, plus a separate key passphrase

Keys made in browser

Only the public key is uploaded; the private key stays locked on the device

Encrypt + sign

Message or file locked for receiver and sender, signed by sender

Decrypt + ✓ Verified

Receiver’s browser unlocks it and checks the signature

The server only sees scrambled text

It checks the ciphertext with BouncyCastle, stores it and pushes it over WebSocket. It never decrypts.

Technologies and why

Next.js

The screens, plus a strict policy against injected scripts

OpenPGP.js

Keys, encryption and signing, all in the browser

Spring Boot

REST API in clean layers: controller, service, repository

Spring Security, JWT, BCrypt

Stateless logins, slow password hashes, rate limits

BouncyCastle

Checks keys and ciphertext on the server. Never decrypts

WebSocket / STOMP

Pushes new messages instantly, once they are saved

PostgreSQL + Flyway

Stores ciphertext; Flyway versions the schema

Docker Compose

Database, backend and frontend in one command

Security highlights

End-to-end encryption

Encrypted and signed in the browser before anything is sent

Zero-knowledge server

No plaintext, private keys or passphrases. Only ciphertext and metadata

Signature verification

✓ Verified badge; a tampered message fails to decrypt

Fingerprints

Computed in the browser and pinned; a key change blocks sending
